## 批次 1：编码、daemon 启动、索引一致性

| 问题 | 影响 | 修复 |
|---|---|---|
| hook 按系统代码页（GBK）解码 stdin | 含中文的文件路径被改坏，编辑后不会重新索引 | 按 UTF-8 解码 |
| CLI 输出到管道时用 GBK | 预览里有 emoji 就崩溃 | stdout/stderr 改为 UTF-8 |
| Windows 上启动锁可能抛 PermissionError | 被当成异常而不是"锁已被占用" | 视为已占用；释放锁不再抛错 |
| 替换 daemon.json 时有客户端正在读 | Windows 上 os.replace 失败（WinError 5），daemon 起不来 | 重试替换 |
| daemon 启动时就崩溃 | 客户端一直等到超时，看不到原因 | 检测子进程退出，立即报错并附上日志末尾 |
| `/health` 只看端口能否连通 | 端口被别的服务或旧 daemon 占用时误判为健康 | 要求返回 ok 且 pid 与 daemon.json 一致 |
| daemon 用普通 `python -m` 启动 | 当前目录里的同名模块会被优先加载 | 改用 `python -I`；崩溃日志限制在 5MB |
| 先更新向量缓存、后提交事务 | 提交失败时缓存里有数据库里没有的块 | COMMIT 成功后才更新缓存 |
| 全量重建先清空、再扫描 | 扫描失败会留下一个空索引 | 先扫描再清空；扫描失败 60 秒内不重试，只有成功的全量扫描才清除错误状态 |
| 模型拒绝某一个块 | 整次更新失败 | 逐条重试，只跳过出错的块 |
| MCP 参数没有约束和说明 | `k`、`modality` 写错时表现为"服务不可用" | 参数 schema 带说明和取值范围；参数错误单独报告；按花括号拆分 glob |
| token 按 str 比较 | 非 ASCII 的 Authorization 头导致 500 | 按 bytes 常数时间比较，返回 401 |
| CLI `reindex` 的相对路径按项目根解析 | 在子目录里执行时指错文件 | 按当前目录解析；支持 `--json` |

## 批次 2：安全

| 问题 | 影响 | 修复 |
|---|---|---|
| `.semsearchignore`、`.gitignore`（回退路径）、`path_glob` 用 Python 正则匹配 | 仓库里的恶意规则可让 daemon 卡死（ReDoS） | pathspec 改用 RE2（线性时间），没有 RE2 时限制通配符数量；限制规则行数和长度 |
| Windows 上 `chmod 0o600` 不起作用 | token 和索引可能被同机其他用户读取 | daemon 启动时给数据目录设置只允许当前用户的 ACL；POSIX 上 700 |
| 可以把主目录、磁盘根、`~/.claude`、`~/.ssh` 当项目索引 | 大量私人文件进入索引 | daemon 拒绝这些根目录；查找项目根时不越过主目录 |
| 敏感文件规则区分大小写 | Windows 上 `.ENV`、`ID_RSA` 不会被排除 | 不区分大小写，任何层级生效；补充更多凭据文件名 |
| 结果里的路径和符号名可能含不可见字符 | 可用双向控制符、零宽字符伪造或隐藏内容 | 去掉不可见字符，长度上限 200，路径和符号名也标注为不可信 |
| 语法树嵌套过深 | 深度 × 大小导致分块耗时爆炸 | 容器最多下钻 30 层 |
| Pillow 按内容嗅探格式 | 可能调用 EPS/Ghostscript 等不需要的解码器 | 只允许索引的图片格式 |
| 模型跟随 Hugging Face 最新版本 | 上游更新会悄悄改变向量 | 固定到测试过的 commit（`SEMSEARCH_MODEL_REVISION`） |
| 安装器的 hook 路径直接拼进 shell 命令 | 路径里的 `$`、`%`、反引号会被展开 | 拒绝这类路径；卸载时只移除自己的 hook；写入前重新合并，避免覆盖其他程序的改动；subagent 文件先备份 |
| post-commit 用工作区安装 | 未提交的改动进入 Claude Code | 从 `HEAD` 快照安装，依赖按 `uv.lock` 锁定 |
| git 仓库里先用 rg 列文件 | 和 hook 的 `git check-ignore` 判断不一致，文件反复增删 | 先用 `git ls-files`；路径前加 `--`；读取带 BOM 的 UTF-16 文件 |

## 批次 3：检索与分块（分块器 v5、关键词 v2，索引自动重建一次）

| 问题 | 修复 |
|---|---|
| 超长单行（压缩代码、内联数据）只有前约 1k token 能被嵌入 | 按 token 上限拆分长行 |
| 压缩/生成文件占满结果 | 平均每行非空白字符超过 500 的大文件跳过 |
| 模块文档字符串、带注释的常量等短片段被丢弃 | 不少于 80 个字符的片段保留成块 |
| JS/TS 箭头函数、Go `type X struct`、Rust `impl<T> S<T>` 没有名字 | 识别这些定义的名字 |
| Rust `#[attribute]` 把文档注释和定义隔开 | 属性和注释一起并入定义 |
| tree-sitter 语法加载失败后永久退回行窗口 | 300 秒后重试 |
| Markdown：`## Learn C#` 末尾的 `#` 被删；围栏关闭判断太宽 | 修正标题正则；围栏只由相同符号和长度关闭 |
| 相同内容的副本挤掉其他结果 | 结果不够时扩大候选池（最多 5000） |
| `3rd`、`10px` 产生 `rd`、`px` 这类关键词 | 数字开头的词不拆 |
| 模型序列长度没给提示词留空间 | 预留提示词和特殊 token |
| 图片未按 EXIF 旋转；16 位灰度图被截断 | 应用 EXIF 方向；16 位按比例缩放 |
| `SEMSEARCH_HOME=""` 被当成当前目录；上限可以设成 0 或负数 | 空值回退到默认目录；上限必须为正 |

## 批次 5：审校后补修（2026-11-03）

批次 4 结束时列为"未修复"的三项，回归测试在 `tests/test_hardening.py`。修复后共 284 个测试通过，覆盖率 90%。

| 问题 | 修复 |
|---|---|
| 媒体解码（PyAV、pdfium、Pillow）在 daemon 进程内解析不可信文件 | 改在子进程 `semsearch.index.media_worker` 里分段和解码。子进程：限制内存（Windows 作业对象 2 GB；POSIX 用 RLIMIT_AS）；Windows 上禁止再启动其他进程，出现未处理异常时直接退出，不弹崩溃对话框；每次调用限时 120 秒。崩溃、卡死或回传格式不对时结束子进程，只影响当前文件，该文件剩下的块不再尝试。子进程只回传 JSON 和不经 pickle 的 numpy 数组，daemon 按请求时的上限逐项检查（形状、类型、页码、时间段、字符串长度）后才使用。媒体评测分数不变（MRR 0.773），首次索引慢约 18% |
| 没有 git 和 rg 时，目录遍历只读根目录的 `.gitignore` | 逐级读取每个目录的 `.gitignore` 和 `.git/info/exclude`，优先级与 git 相同（深层覆盖浅层，同一文件里后面的规则覆盖前面的）；被忽略的目录不进入。hook 的单文件判断用同一套规则。测试中与 `git ls-files` 的结果逐个对比一致 |
| 请求体没有大小上限、没有频率限制 | 请求体上限 1 MB（看 Content-Length，分块上传时边读边计），超出返回 413；同时处理的连接最多 32 个，超出返回 503；令牌桶限速每秒 20 次、可突发 100 次，超出返回 429 并带 Retry-After。限速只统计持有 token 的请求，`/health` 不限速。客户端遇到 429/503 会按 Retry-After 等待后重试，等待不超过 5 秒且不超过本次请求的超时 |

## 仍然存在的限制

| 问题 | 风险 | 现状 |
|---|---|---|
| 媒体子进程不是完整沙箱 | 解码库被攻破后，子进程能以当前用户身份读取文件 | 内存、子进程数量、运行时间已受限；文件访问权限与用户相同 |
| 子进程里的代码统计不到覆盖率 | daemon 和媒体子进程都用 `-I` 启动，不加载覆盖率钩子 | 用真实子进程和模拟子进程（崩溃、卡死、错误回传）的测试覆盖 |
| 安装器的备份是原文件的完整副本 | `~/.claude.json` 里的 token 也在备份里 | 已在 README 说明 |
