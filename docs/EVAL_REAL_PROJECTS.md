# 真实项目评测

日期：2026-11-03

在 6 个私人项目上做了一轮评测。为保护隐私，题目、结果和完整报告只保存在作者本地的 `evals/private/` 下，不进入公开仓库。本文只给出汇总数字和方法。

## 结论
- **共 72 道题**：
  - 第一轮成绩偏低，MRR 0.53。
  - 逐题查原因后发现，问题出在评分规则和分块方式上，不是检索模型本身。
  - 两处修好后，MRR 达到 **0.81–0.83**，正确答案进前 5 的比例为 92–96%。
- **分块器 v4**：
  - 函数正上方紧贴的注释，现在和函数归入同一块。以前注释单独成块，而且常常排在函数前面。
  - PowerShell 函数单独成块。以前整个文件都按行窗口切。
  - 这两处改动让中文直接查询的 MRR 从 0.58 升到 0.78。这些项目里有大量中文注释，现在它们和代码在同一个块里。
- **先翻成英文再查**仍然有用，只是收益变小了：中文题 MRR 从 0.77 升到 0.80，R@5 从 86% 升到 93%。
- **混合检索不再有可测的收益**：126 道题（本轮 72 道加原评测集 54 道）合计，纯向量 MRR 0.778，hybrid 0.774。所以默认改回了纯向量。

## 项目
| 项目类型 | 主要语言 | 索引文件数 | 块数 |
|---|---|---|---|
| 6 个游戏 mod / 工具项目，其中 3 个附带反编译的游戏代码 | C#、TypeScript、GDScript、PowerShell、JavaScript | 共约 16,000 | 共约 106,000 |

最大的项目有 8,000 个文件、约 6 万个块，首次索引要 26 分钟（RTX 3060 6GB）。

## 题目
- 每个项目 10–14 道题。
- 题目由没参与开发的子代理读代码后编写，每个答案都核对过源码。
- 约 2/3 的题针对作者自己写的代码，1/3 针对反编译的游戏代码。
- 题型：
  - 中文概念题 36 道
  - 英文概念题约 20 道
  - 标识符加描述的混合题 16 道
- 中文题的英文版由另一个没看过代码的模型盲译。

## 过程
| 轮次 | 改动 | hybrid MRR | hybrid + 翻译 MRR | hybrid + 翻译 R@5 |
|---|---|---|---|---|
| 1 | 初次运行 | 0.533 | 0.596 | 0.78 |
| 2 | 修评分规则 | 0.651 | 0.728 | 0.93 |
| 3 | 分块器 v4 | **0.804** | **0.827** | **0.96** |

第 1 轮有 12 道题，三种模式都没把答案排进前 10。逐题诊断后分成三类：
1. **评分误判（6 道）**：小文件和小类是整块索引的，块的符号名是文件名或类名，和题目要求的方法名对不上，但正确文件其实排在第 1–2 名。修正后的规则是：结果块的行范围只要覆盖目标的定义行，就算命中。
2. **注释与函数分家（4 道）**：排第一的是函数正上方那几行注释单独组成的块。
3. **PowerShell 函数没被识别（4 道）**。

第 3 轮各项目的 MRR 在 0.75 到 0.95 之间。只有 4 道题的答案没进前 3，都是很长、细节很多的中文问题。

原评测集（54 道）在分块器 v4 下也有提升：hybrid MRR 从 0.690 升到 0.734，中文题从 0.583 升到 0.691。

## 代码审查
分块改动经审查后修了两处：
- Rust 的 `///` 文档注释原来不会并入函数，因为这种语法的行注释结束位置落在下一行行首。
- 类定义 `{ // 注释` 那一行原来会被并入第一个方法。现在要求注释所在行、注释之前不能有代码。

评分规则也收紧了：优先找带声明关键字的行，找不到才退回第一次出现的非注释行。修完后重建索引重跑，数字不变。

已知限制：
- 文档注释和定义之间如果隔着 Rust 的 `#[...]`、TS 的装饰器或 C++ 的 `template` 行，注释不会并入定义（和改动前一样）。
- 紧贴在第一个定义上面的许可证注释，会被并入这个定义。

## 复现（用你自己的项目）
```bash
uv run python evals/index_projects.py <项目根目录> ...
uv run python evals/run.py <题目文件.json> ... --modes "vector,hybrid,hybrid;tr=1" --show-misses --strict
```
- 题目文件格式见 `evals/cases/semsearch.json`。`project` 可以写绝对路径、`~/...`，或相对仓库根目录的路径。
- 放在 `evals/private/cases/` 下的题目和 `evals/private/translations_en.json` 会自动读取，并且不会被提交。
- `--strict`：题目里的答案路径不在索引中时直接报错。
